================================================================================
CinePass — GUIDE D'INSTALLATION (Web, Android, iOS + backend Serverpod)
Projet : application de reservation d'evenements (cinema, concerts, etc.)
================================================================================

--------------------------------------------------------------------------------
1. PREREQUIS
--------------------------------------------------------------------------------
- Git
- Flutter SDK (stable) + Dart
- Docker Desktop
- Android Studio (emulateur Android)
- Xcode + CocoaPods (uniquement sur macOS pour compiler iOS)

Verifications :
  flutter --version
  dart --version
  docker --version
  flutter doctor

Serverpod CLI (si besoin de regenerer le client) :
  dart pub global activate serverpod_cli

7. SCHEMA METIER + DONNEES DE TEST (FORTEMENT RECOMMANDE)
--------------------------------------------------------------------------------
Remplacer le nom du conteneur si different : docker ps (souvent cine_pass_server-postgres-1).

Windows PowerShell (depuis cine_pass_server) :

   Get-Content schema\cine_pass_schema.sql -Raw      | docker exec -i cine_pass_server-postgres-1 psql -U postgres -d cine_pass
  Get-Content schema\seed_data.sql -Raw             | docker exec -i cine_pass_server-postgres-1 psql -U postgres -d cine_pass

Alternative Windows (cmd) :

   type schema\cine_pass_schema.sql      | docker exec -i cine_pass_server-postgres-1 psql -U postgres -d cine_pass
  type schema\seed_data.sql             | docker exec -i cine_pass_server-postgres-1 psql -U postgres -d cine_pass

macOS / Linux (depuis cine_pass_server) :

   docker exec -i cine_pass_server-postgres-1 psql -U postgres -d cine_pass < schema/cine_pass_schema.sql
  docker exec -i cine_pass_server-postgres-1 psql -U postgres -d cine_pass < schema/seed_data.sql

--------------------------------------------------------------------------------
10. APPLICATION ANDROID — EMULATEUR
--------------------------------------------------------------------------------
Important : sur l'emulateur, 127.0.0.1 designe l'emulateur lui-meme, PAS le PC.
Utiliser l'alias 10.0.2.2 pour joindre le serveur sur la machine hote.

Demarrer l'emulateur (Android Studio > Device Manager), puis :

  flutter devices
  flutter run -d emulator-5554 --dart-define=API_URL=http://10.0.2.2:9080

(Remplacer emulator-5554 par l'ID affiche par flutter devices si besoin.)

Sans --dart-define=API_URL, l'app peut rester configuree sur http://127.0.0.1:9080
et echouer avec "Connection refused" sur Android.

--------------------------------------------------------------------------------
11. APPLICATION ANDROID — TELEPHONE PHYSIQUE (meme Wi-Fi que le PC)
--------------------------------------------------------------------------------
Trouver l'adresse IPv4 du PC (ipconfig sur Windows, ifconfig/ip sur Mac/Linux).

  flutter run -d <DEVICE_ID> --dart-define=API_URL=http://<IP_DU_PC>:9080

Exemple :

  flutter run -d 104883735H004624 --dart-define=API_URL=http://192.168.1.160:9080

--------------------------------------------------------------------------------
12. APPLICATION iOS
--------------------------------------------------------------------------------
La compilation iOS necessite macOS et Xcode.

  cd cine_pass/cine_pass_flutter
  flutter pub get
  flutter run -d ios

Sous Windows seul : prevoir un Mac, un emulateur cloud, ou une CI pour le build iOS.

--------------------------------------------------------------------------------
13. VERIFICATION RAPIDE (SOUTENANCE)
--------------------------------------------------------------------------------
1) Le serveur repond (pas d'erreur au demarrage).
2) L'app affiche l'accueil et la liste des evenements.
3) Connexion / inscription utilisateur.
4) Parcours reservation (selon implementation) et affichage des billets.

--------------------------------------------------------------------------------
14. PROBLEMES FREQUENTS
--------------------------------------------------------------------------------
- Connection refused + 127.0.0.1 sur telephone ou emulateur
    => Utiliser API_URL avec IP du PC ou 10.0.2.2 (emulateur).

- Port 9080 deja utilise
    => Arreter l'ancienne instance du serveur (processus Dart).

- Migrations manquantes
    => Relancer : dart run bin/main.dart --apply-migrations
